01 — Why

CI shouldn't be the bottleneck.

Every team eventually hits the wall: a busy main branch, flaky tests, and a merge button that turns into a coin flip. The fix isn't more runners — it's a queue that's smart enough to know what to run.

N.01
Stacked PRs that conflict on merge.
Two engineers ship in parallel. Both go green. Both press merge. The second one breaks main, and now Slack is on fire.
N.02
Test suites that take too long.
A 40-minute CI run for a one-line README change. You either burn the compute or skip the tests — neither is good.
N.03
Flakes that silently erode trust.
When "rerun until green" becomes muscle memory, real bugs land. Trust in the suite collapses, and so does the value of the gate.

05 — Common questions

The honest answers, up front.

Do I have to rewrite my GitHub Actions?
No. Lattice reads the results of whatever pipelines you already run. Most teams keep their existing YAML completely untouched. The only thing you change is which user clicks "merge" — and that's now Lattice.
How is "selective testing" actually safe?
Lattice builds a real dependency graph by walking imports, build inputs, and (optionally) runtime traces. A test is only skipped if there's no reachable path from the changed files to its assertions. We publish the proof per PR so you can audit any decision.
Does it work with monorepos? Polyrepos?
Both. The queue, graph, and selective testing all work across any number of repos. Most teams that adopt Lattice have a mixed setup, and the dashboard stitches it together into a single view.
What about flaky tests we already have?
Lattice ingests your last 14 days of CI history on connect, identifies tests that fail under your threshold (default 4%), and quarantines them on day one. You'll usually see your green rate jump within an hour.
Where does our code live during all this?
Lattice never stores your source. We hold metadata — file paths, test IDs, timings, graph edges — and stream code through during analysis. Enterprise plans can run the analyzer entirely inside your own VPC.
Can I try it on one repo before rolling out?
Yes, that's the recommended path. Install the app on a single repo, let Lattice shadow your merges for a week (it'll show what it would have done without taking over), then flip the switch when you're convinced.
