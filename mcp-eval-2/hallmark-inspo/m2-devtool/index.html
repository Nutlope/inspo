Four things it does, well.

Convex isn't a chat box bolted onto your repo. It's a reviewer with a job to do — and the job has four steps. Here is what happens between git push and Merge.

01 · Index

It reads the repo, not just the diff.

On install, Convex walks the tree and builds a graph of your code's callers, callees, and test coverage. Every review starts from that graph — so when you touch dequeue(), it already knows which seven jobs and four tests depend on it.

  • Re-indexes on push; no nightly job to forget.
  • Tree-sitter parsers for 14 languages, including SQL migrations.
  • Stores embeddings on your own object store — S3, R2, or filesystem.

02 · Review

It comments where the bug is, in the line that owns it.

Every comment is a hypothesis the reviewer can apply, edit, or refuse. No "consider refactoring" filler — if Convex doesn't have a concrete patch to propose, it stays quiet.

  • Suggested commits, not pull-quotes — apply in one click.
  • Reads CODEOWNERS so it tags humans for blast-radius changes.
  • Routes around files you've marked @convex-skip.

03 · Watch

It waits for your tests, not its own confidence.

Convex doesn't merge on vibes. It runs your existing checks — the ones in .github/workflows, your branch-protection rules, your required reviews — and it watches them tick. When any required check fails, it explains the failure inline and stops.

  • Speaks Required Status Checks, GitHub Apps, and GitLab MR pipelines.
  • Re-runs only the test files reachable from the diff.
  • Surfaces flake history; a flake is named, not silently retried.

04 · Merge

It merges when the gates are green. Not before.

Convex inherits the merge rules you already enforce: required approvals, status checks, CODEOWNERS for sensitive paths, signed commits. When every gate is green, it squashes and merges — and writes a release note in the voice of your last fifty.

  • No backdoor merges; respects branch protection precisely.
  • Generates a Conventional Commit body if your repo uses them.
  • Posts a one-line summary into Slack or Linear if either is wired in.

Things engineering leads ask first.

Does my code leave my network?

Two modes. The hosted mode sends the diff and a scoped slice of the repo graph to Convex's inference endpoint; embeddings live in your S3 or R2 bucket, never ours. The self-hosted mode (convex serve) keeps the whole loop on your own GPU. Bring your own model weights or use the bundled one.

What stops it from merging something broken?

Your existing branch protection rules. Convex doesn't get a merge button you don't already have configured — required approvals, status checks, CODEOWNERS, signed commits, all of it. If you require two human approvals today, Convex still requires two human approvals tomorrow.

Which languages does it understand structurally?

TypeScript, JavaScript, Python, Go, Rust, Ruby, Java, Kotlin, Swift, C, C++, C#, PHP, plus SQL migrations parsed against the dialect declared in your project. Everything else gets line-level review but no graph context.

Can I keep using my own reviewer bot?

Yes. Convex tags itself as one reviewer; your existing required reviewers stay required. You can also gate it behind a label — only PRs tagged convex get reviewed.

How does it handle monorepos?

Cleanly. Index once at the repo root, declare your convex.toml with project boundaries, and reviews are scoped to the package the diff touches. Cross-package changes get cross-package context.

What does it cost?

Free for personal repos and open source. For teams, $24 per active reviewer-seat per month — billed on humans, not diffs. A reviewer-seat is anyone who pushed code that Convex reviewed in the last 30 days. Self-hosting is licensed flat at $1,200/year per organisation.
