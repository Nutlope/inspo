Three things go in. One sentence comes out.

job graph

Which steps ran, in what order, on which runner, and which of them were waiting on something else. A step that failed because its dependency failed is not the break.

step output

Compiler errors, test failures, resolver output, exit codes. Read as a stream to be diffed against the last green run, not as a wall to be scrolled.

runner state

Image version, cache hits, available disk, clock. An environmental break looks identical to a code break until you put the two machines side by side.

How it decides

  1. Find the last green run

    Same pipeline, same branch policy, same runner class. This is the reference trace everything else is measured against.

  2. Diff everything between them

    Commits, lockfiles, runner images, cache keys, environment variables, and the shape of the job graph itself. Most runs differ in more places than anyone expects.

  3. Rank the differences against the failure

    A dependency bump that changed a resolver line quoted in the error outranks a README edit. Candidates that explain nothing in the output are dropped rather than listed.

  4. Write it in one sentence

    The notice leads with the cause and keeps the evidence underneath it. When nothing explains the failure, it says that instead of guessing, and it says so first.

Questions platform teams ask first

Does it need access to our source?

No. It reads the pipeline’s own output: job graph, step logs, runner metadata. Source access is optional, and it is only used to attribute a candidate to a specific diff.

What happens when the break is a flake?

It says so. When the same step fails and passes across identical inputs, the notice names the flake and its rate over the window rather than inventing a cause for it.

Which CI systems can it read?

Anything that can post a run’s job graph and logs to a webhook. The current runner list lives in the docs, because it changes faster than a landing page does.

Where does the notice go?

Wherever the team already looks when a build goes red: the pull request, a chat channel, or the pipeline’s own run summary. It is not another dashboard to remember.
