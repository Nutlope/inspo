A verdict is four readings, laid over each other.

Sightline pulls the run apart the way you would at 9am with Slack already asking, and keeps only the reading that explains the failure.

It reads what your pipeline already emits.

job graph
The provider’s own run structure: which step failed first, and which steps only failed because that one did.
logs
Streamed, not stored twice. Sightline keeps the frames it cited and drops the rest at the retention you set.
test reports
JUnit XML and the provider’s native format, matched to the tests they belong to across runs.
version control
The commit range, the diff surface, and who was in it, read at the same moment the run started.

No agent, no sidecar. Sightline connects to the provider you already use and reads the run after it finishes. Nothing runs inside your jobs, so nothing new can break them.

If a verdict is wrong, say so on the pull request. The correction is stored against the pipeline, not against a model you cannot see.

The verdict goes where the failure was already being discussed.

On the pull request

One comment, edited in place as later runs change the answer. It never posts twice for the same failure, and it deletes itself when the run goes green.

In the channel

The same four lines, threaded under the failure notification your provider already sends, so nobody opens a second tab to find out what happened.

As an API response

Every verdict is readable as JSON, keyed by run, if you would rather put it in front of people your own way.

What it will not tell you.

It does not review your code.

Sightline explains why a run failed. Whether the change was a good idea is still your call, and still a human’s.

It cannot see what the run did not record.

A job that swallows its own output leaves nothing to correlate. Sightline will say the evidence is missing rather than guess at a cause.

It does not rank your team.

There is no leaderboard, no per-author failure count, and no scoring of anybody. The unit of analysis is the run.

Connect one pipeline and let the next failure explain itself.

Read access to a single repository is enough to start. Nothing is written back until you turn the pull-request comment on.
