How it works

Three steps from prompt
to a phone that answers.

No media servers, no STT/LLM/TTS plumbing, no glue code. Larynx is the runtime that holds the call open and orchestrates every turn for you.

01 — Write

Define the agent

Describe behavior, attach your tools, pick a voice. Plain code, fully typed.

# agent.py
agent = Agent(
  voice="ember",
  tools=[refund, lookup],
)
02 — Connect

Attach a number

Claim a Larynx number or bring your own SIP trunk. Routing is one line.

# route it
larynx numbers attach \
  +14155550148 \
  --agent support
03 — Deploy

Go live, then watch

Ship to the edge in seconds. Every call streams a transcript, traces & metrics.

# ship
larynx deploy
→ live in 4 regions

The runtime

Built for the part that's
actually hard: the conversation.

Latency, interruptions, and recovery are where voice agents break. Larynx handles them at the runtime layer so your agent code stays simple.

Turn-taking under 300 ms

Streaming ASR and speculative generation overlap, so the agent starts replying before the caller finishes — it feels like a real conversation, not a kiosk.

287 ms p50

Native barge-in

Callers interrupt and the agent yields instantly — no awkward talk-over, no lost context.

Every call, transcribed

Live transcript, recording, tool traces and timing on every call — searchable, exportable.

Function-calling, mid-sentence

Your agent can hit your API, look up an order, or book a slot while it's still talking — results stream back into the turn so the caller never waits in silence.

Bring your own stack

Any LLM, any voice provider, any SIP trunk. Swap models without touching your agent.

Observability that speaks call

P50/P99 turn latency, interruption rate, drop-offs and per-tool timing — broken down by agent, number, and region. Replay any call frame-by-frame to see exactly what it heard.

Fails gracefully

Provider hiccup? Larynx falls back, retries, and hands off to a human before the line goes quiet.
